# Scai GUI 重置实施方案（基于 docs/ui参考 设计稿）

> 依据：`docs/ui参考/` 下 5 张高保真稿 + `说明.md` 设计系统。本文档是落地执行方案，含设计稿问题修正、技术选型、架构、分阶段计划与验收标准。

## 1. 设计稿与现状差距总览

设计稿定的方向是对的：**三卡总览 + 风险筛选标签页 + 主数据表 + treemap 可视化 + 右侧详情 + 底部决策栏**，比现版 tkinter 表单风强一个档次。逐项对照现有功能：

| 设计稿元素 | 现状 | 工作量定性 |
|---|---|---|
| 三张统计卡（根目录总量/可清理/需确认） | 无（只有状态栏文字） | 新增；根目录总量需引擎补充 |
| 筛选标签页带计数（全部 1,268…） | 有筛选、无计数 | 小改 |
| 数据表（名称/类型/大小/风险标签/分类/修改时间） | 有（Treeview） | 重做 UI |
| 风险胶囊标签（色底色字+锁图标） | 纯文字着色 | 重做 UI |
| treemap 目录占比（点击联动列表） | 无 | 新增，最大单项 |
| 右侧详情面板 | 有（底部 6 行文本） | 重排 |
| 底部决策栏（已选汇总+绿色主按钮+次按钮组） | 有（功能同） | 重排 |
| 空态欢迎页 | 无（直接进主界面） | 新增 |
| 扫描进度页（实时目录/文件计数+进度条+取消） | 有进度条，无实时计数、无取消 | 引擎加回调+新增取消 |
| 删除确认弹窗（清单+琥珀警示条） | 有（messagebox 简陋版） | 重做 |
| 明暗双主题 | 无 | 跟随技术栈 |
| "上次扫描"日期 | 无（只记上次目录） | 小改状态文件 |

## 2. 设计稿本身需要修正的 4 个问题（实施前定案）

1. **【违反产品铁律】** 主界面详情面板"建议动作"写了"移到回收站（可恢复）**或永久删除**"。这是需求书明令禁止的措辞。修正为只保留"移到回收站（可恢复）"，全文档、全文案不得再出现永久删除。
2. **侧边栏两处不一致且含虚构功能**：扫描中稿的侧边栏（大文件/重复文件/缓存文件/安装包/不常用文件/空文件夹）与删除确认稿的侧边栏（智能扫描/清理建议/应用管理/更多工具）互相矛盾，且主界面稿根本没有侧边栏；这些条目对应的功能（重复文件检测、应用管理等）**并不存在**。修正：本期**不做侧边栏**，跟随主界面稿的单窗体三段式布局；侧边栏等将来真有多个模块再做。
3. **主按钮颜色不统一**：空态"开始扫描"是绿色，设计系统与结果页头部是蓝色。定案：**扫描类主操作 = 品牌蓝 #3B82F6；"移到回收站" = 安全绿 #22C55E**（绿色语义 = 可恢复的安全动作，贯穿确认弹窗确认键）。
4. **数字诚实性**：标签页计数"全部 1,268"与 treemap"其他 653.2 GB"暗示全量数据，而引擎是 Top-N 分析（默认 200 条）。定案：计数如实显示分析条数（如"全部 200"），treemap 的"其他"标注为"未展开/更小项"；GUI 默认 limit 提到 500，列表底部提供"加载更多"。不制造虚假的"全量"印象。

另有两处按需简化：扫描"预计剩余"时间没有可靠依据，改为显示已用时+实时计数，不做 ETA（若后续有稳定速率数据再加）；treemap 本期用自绘 squarified 矩形树图（无第三方图表库），支持悬停高亮与点击选中，不做缩放动画。

## 3. 技术选型

### 推荐：方案 B —— pywebview + 本地 HTML/CSS/JS（1:1 还原设计稿）

| 维度 | A：customtkinter | **B：pywebview + HTML（推荐）** | C：Tauri/Electron 重写 |
|---|---|---|---|
| 设计稿还原度 | ~70-80%（胶囊标签/卡片可行，treemap 需 Canvas 自绘，hover/动画/主题切换费力） | **~100%**（CSS 直接实现胶囊/卡片/暗色主题；treemap 自绘 SVG 约 80 行 JS） | ~100% |
| Python 引擎复用 | 完整 | **完整**（js_api 桥接，扫描/回收站/日志零改动迁移） | 需重写核心 |
| 运行时依赖 | +customtkinter（打进 exe） | +pywebview/pythonnet（打进 exe），系统需 WebView2（Win10/11 预装，缺失时检测并给出一键跳转下载+回退旧版 GUI 的提示） | WebView2 或 Chromium |
| exe 体积 | ~13 MB | ~16-20 MB | 更大/更小（Tauri） |
| 单文件便携打包 | 成熟 | 成熟（PyInstaller 有官方冻结指南） | 不同工具链 |
| 后续维护 | tkinter 天花板低，每次加视觉都要斗智斗勇 | Web 技术栈，改 UI 成本低 | 双语言栈 |
| 工期 | ~4-5 人日 | **~7-8 人日** | 1-2 月 |

选 B 的理由：设计稿的胶囊标签、卡片、treemap、暗色主题正是 tkinter 的天花板之外；一次迁移到位，后续 UI 迭代都在低成本区。C 直接排除（重写扫描/回收站核心，偏离 Python 资产）。

**稳健备选 A**：若要求"绝不引入新运行时依赖/绝不容忍 WebView2 缺失场景"，退回 customtkinter + Canvas 自绘 treemap，接受 70-80% 还原度（无平滑 hover、暗色主题手工调、圆角有限）。

## 4. 目标架构（方案 B）

```
scai_gui.py            # 保留：回收站(move_to_trash*)、日志、状态文件、GuiRow 纯逻辑
scai_gui_web.py        # 新：pywebview 窗口 + JsApi 桥（scan/cancel/select/plan/trash/log/prompt/state）
web/index.html         # 新：单页（空态/扫描态/结果态 三态切换）
web/style.css          # 新：设计 Token（CSS 变量，明暗主题）+ 组件样式
web/app.js             # 新：状态机、表格、筛选、选择汇总、删除流程
web/treemap.js         # 新：squarified treemap（SVG，悬停/点击联动）
web/icons.js           # 新：内联 Lucide SVG（离线，不引 CDN）
scai.py                # 小改：扫描进度回调 + 可取消 + 根目录总量
scai_gui_main.py       # 改：入口走 scai_gui_web；WebView2 缺失时回退旧 tkinter GUI
```

桥接口（js_api，全部返回 JSON）：`get_state` / `browse` / `scan(path, include_all, limit)` / `cancel_scan` / `toggle(rowKey)` / `set_filter` / `auto_plan(target)` / `confirm_trash(paths)` / `open_log` / `reveal(path)` / `ai_prompt()` / `set_theme`。

安全不变式（桥层强制，前端不可绕过）：`confirm_trash` 服务端再次过滤 `risky` 与父子重叠；不存在"删除"语义的接口，只有 `move_to_trash`；其余逻辑（去重、目标勾选、日志）全部复用现有 Python 实现。

### 引擎小改（scai.py，向后兼容）

- `scan_top_files/scan_top_dirs` 增加可选 `progress_cb(stats)`（每 N 条调用一次）与 `cancel_check() -> bool`（返回 True 中止并返回已完成部分）；
- `scan_top_dirs` 返回根目录聚合记录（总量卡片数据源）；
- 现有 CLI/TUI 行为不变（参数默认 None）。

## 5. 分阶段实施计划（方案 B，约 7-8 人日）

**P0 引擎准备（0.5d）**：进度回调、取消、根总量、`last_scan_at` 状态。验收：CLI/TUI 回归通过，`python scai.py` 行为与现状一致。

**P1 Web 壳与桥（1d）**：pywebview 窗口、JsApi、三态空壳、状态持久化、`SCAI_GUI_SMOKE_MS` 等价的自关闭测试钩子。验收：exe 外源码可启动，桥方法可从 JS 调通。

**P2 结果态主界面（2d）**：三统计卡、筛选标签页（带如实计数）、数据表（胶囊风险标签、行内勾选、高风险锁行）、右侧详情面板、底部决策栏（已选汇总/主次按钮）、"显示默认排除目录"开关、按目标勾选。验收：与主界面稿逐区对照；勾选/去重/汇总与旧版行为一致（用旧 GUI 逻辑做基准对照）。

**P3 空态与扫描态（1d）**：欢迎页（预填上次目录+上次扫描日期）、蓝色开始扫描、全盘入口含耗时提示、扫描进度页（实时计数+已用时+取消按钮）。验收：取消后已扫描部分可用或干净取消；空态→扫描→结果全流程顺滑。

**P4 删除流程（1d）**：确认弹窗（清单预览 8 项+"以及另外 N 项"+琥珀警示条+绿色确认键）、结果反馈（释放空间/失败原因）、打开日志、打开位置。验收：回收站删除用 PowerShell 验证计数变化（沿用上轮测试法）；审计日志逐条落盘。

**P5 treemap 与暗色主题（1.5d）**：squarified treemap（按风险着色，"其他"聚合，悬停高亮、点击定位列表行）、明暗主题切换（CSS 变量，偏好入状态文件）。验收：点击色块定位正确；两主题下风险色均达对比度标准。

**P6 打包分发与回归（1d）**：build_exe.py 增加 web 资源打包（`--add-data`）与 pywebview hidden imports；启动时 WebView2 检测（缺失→提示+回退旧 GUI）；重建 `scai.exe`/`scai-gui.exe`、`scai-skill.zip`；从全新目录便携性验证；README/截图更新。

## 6. 测试与验收基线

- 逻辑层（无头 pytest 风格脚本）：桥接口、去重、目标勾选、日志、状态文件；
- UI 冒烟：自关闭钩子跑三态切换、删除全流程（模拟确认）；
- 安全回归：risky 行不可勾选（前端禁用+桥层双重拦截）、回收站计数验证、文案全文无"永久删除"；
- 便携回归：zip 解压到全新目录运行两 exe；
- 性能：500 条 limit 下扫描→渲染 < 1s（不含扫描本身）；treemap 60fps 悬停。
