## 二、设计系统详解

### 2.1 风险色（全应用一致）

| 风险等级 | 语义        | 浅色主题      | 深色主题      |
| :--- | :-------- | :-------- | :-------- |
| 可清理  | 安全删除      | `#22C55E` | `#4ADE80` |
| 需确认  | 建议人工核对    | `#F59E0B` | `#FBBF24` |
| 高风险  | 系统管理，只读锁定 | `#EF4444` | `#F87171` |

辅助色：

* 品牌蓝（扫描/进度）：`#3B82F6`
* 中性灰阶：`#F8FAFC` / `#F1F5F9` / `#E2E8F0` / `#94A3B8` / `#475569` / `#1E293B`

### 2.2 字体

```
font-family: "Microsoft YaHei UI", "PingFang SC", "Segoe UI", sans-serif;

```

字号比例：

* 大标题：24px / 32px 行高
* 区域标题：20px / 28px 行高
* 卡片数字：32–40px（等宽、加粗）
* 正文/列表：14px / 22px 行高
* 辅助/标签：12px / 18px 行高

数字统一使用等宽字体变体或 `font-variant-numeric: tabular-nums`，保证大小列右对齐。

### 2.3 间距系统

`4 / 8 / 12 / 16 / 24 / 32 / 48 px`

典型应用：

* 表格行高：34px
* 卡片内边距：16px
* 区域间距：24px
* 窗口最小尺寸：960×640px

### 2.4 组件状态

**按钮**

* 主按钮：绿底 `#22C55E` + 白字，悬停 `#16A34A`
* 次按钮：白底 + 灰边框 `#E2E8F0`，悬停背景 `#F8FAFC`
* 危险主按钮：红底 `#EF4444` + 白字（仅用于不可逆入口，本应用不出现）
* 禁用态：背景 `#E2E8F0` + 文字 `#94A3B8`

**风险标签**

* 可清理：绿底 `#DCFCE7` + 绿字 `#166534`
* 需确认：琥珀底 `#FEF3C7` + 琥珀字 `#92400E`
* 高风险：红底 `#FEE2E2` + 红字 `#991B1B` + 锁图标
* 高风险行：整行背景 `#FEF2F2`，复选框替换为锁图标，不可交互

**开关/复选框**

* 选中态：品牌蓝 `#3B82F6`
* 未选中：灰边框 `#CBD5E1`
* 禁用：灰底 `#E2E8F0`

## 三、交互流程说明

### 3.1 扫描流程

1. **空态**：路径输入框预填上次目录，用户可浏览修改。
2. 点击「开始扫描」后，顶部扫描区折叠或置灰，主区域切换为扫描进度面板。
3. 扫描中显示：已扫描目录数、已扫描文件数、已用时间、预计剩余、进度条。
4. 全盘扫描入口处常驻提示「全盘扫描可能需要数分钟」。
5. 扫描完成自动切换至结果态，列表默认按大小降序，筛选标签默认「全部」。

### 3.2 浏览与筛选

* 顶部筛选标签：全部 / 可清理 / 需确认 / 高风险。
* 切换筛选时，列表即时过滤，底部已选汇总保持实时准确。
* 「显示默认排除目录」开关：开启后列表追加系统排除项，仅作展示，仍为锁定态。
* 列表行点击选中并在右侧/底部展开详情面板。
* 可视化区域（treemap/环形图）与列表联动：点击色块可定位到对应条目。

### 3.3 选择与汇总

* 勾选行内复选框加入选择集。
* 父子去重逻辑：若勾选父文件夹，子项不再重复计入件数与大小。
* 底部决策区实时显示：「已选择 N 项，共 X.X GB」。
* 「按目标勾选」：用户输入如 `20g`，系统按「可清理优先 → 需确认次之」自动选择最接近目标且不包含高风险的方案。

### 3.4 删除确认

1. 点击「移到回收站」弹出模态确认框。
2. 弹窗清单预览前 8 项，超出显示「…以及另外 N 项」。
3. 文案明确：「将移到回收站，可从回收站恢复」。
4. 若所选包含「需确认」项，展示琥珀色警示条。
5. 用户点击确认后执行删除，界面进入结果反馈态。

### 3.5 删除后反馈

* 成功：显示释放空间大小、成功项数，建议「重新扫描」按钮。
* 失败：列出失败项及原因（权限不足、文件被占用等）。
* 每次删除写入 `~/.scai/cleanup-log.jsonl`，可通过「打开日志」查看。

### 3.6 错误态

* 路径不存在、权限失败：使用行内 toast/提示条，不阻断整个窗口。
* 高风险项尝试删除：前端直接拦截，无需后端请求。

## 四、图标建议

建议统一使用线性风格图标，线宽 1.5–2px，圆角端点。

| 用途     | 图标建议                        | 说明        |
| :----- | :-------------------------- | :-------- |
| 文件夹    | `folder`                    | 列表中代表目录   |
| 文件     | `file` / `document`         | 列表中代表文件   |
| 扫描     | `scan` / `radar`            | 开始扫描按钮    |
| 全盘扫描   | `hard-drive`                | 全盘入口      |
| 回收站    | `trash-2`                   | 移到回收站主按钮  |
| 警告     | `alert-triangle`            | 需确认警示     |
| 锁      | `lock`                      | 高风险只读     |
| AI 提示词 | `sparkles` / `copy`         | AI 诊断复制   |
| 日志     | `scroll-text` / `file-text` | 审计日志      |
| 打开位置   | `external-link`             | 资源管理器定位   |
| 勾选/复选框 | `check-square` / `square`   | 选择态       |
| 设置     | `settings`                  | 应用设置（如需要） |

推荐图标库：Lucide、Heroicons、Feather Icons（均可免费商用，风格统一）。

## 五、技术栈建议与迁移成本

当前实现为 Python + tkinter。按新设计视觉复杂度排序：

### 方案 A：customtkinter（推荐·低成本）

* **适用性**：可直接保留 Python 生态与单文件 exe 打包流程。
* **能力**：支持圆角、现代按钮、标签、滑出面板的视觉实现，能满足 80% 设计稿。
* **局限**：复杂 treemap/环形图、平滑动画、高分屏字体渲染仍需自行绘制或引入 Matplotlib/ttkbootstrap。
* **迁移成本**：低，1–2 周可完成主体重构。

### 方案 B：pywebview + HTML/CSS/JS（中成本·高表现力）

* **适用性**：Python 负责扫描与文件操作，前端用 HTML/CSS/JS 渲染 UI。
* **能力**：可完全还原设计稿，treemap/环形图可用 D3/ECharts 实现，动画与主题切换方便。
* **局限**：打包体积增大（需内嵌 Chromium/Edge WebView2），离线运行依赖 WebView2 运行时（Win10/11 已预装）。
* **迁移成本**：中，2–4 周；适合希望长期维护、视觉要求高的版本。

### 方案 C：Tauri / Electron（高成本·完全重写）

* **适用性**：Rust/Node 重写核心，前端框架任选。
* **能力**：原生体验最佳，打包体积小（Tauri）。
* **局限**：需重写扫描与回收站逻辑，偏离现有 Python 资产。
* **迁移成本**：高，1–2 个月；建议仅在产品成熟后考虑。

### 建议

* **短期（MVP 视觉升级）**：customtkinter，快速交付现代感界面。
* **中期（高保真完全还原）**：pywebview + 本地 HTML，保留 Python 核心逻辑同时获得完整设计表现力。
